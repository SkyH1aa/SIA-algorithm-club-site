供应商配置

只保存供应商标识、Base URL、API 协议、认证头和 Supabase Secret 名称，不在页面输入或回显 API Key。

自动模式沿用 URL 推断：messages/message 结尾使用 Messages，chat/completions 结尾使用 Chat Completions，其余使用 Responses。显式选择协议会覆盖 URL 后缀，由后端使用对应端点。

模型配置

模型参数用于普通 Chat 目录和管理员测试。供应商密钥仍由后端 Secret 读取。

模型继承所选供应商的 API 协议；请在供应商配置中修改。切换协议不会自动修改模型的思考配置或供应商的认证头。

新配置默认不发送思考参数，以兼容中转与历史重放。思考计入输出预算；手动预算须为至少 1024 的整数，严格小于默认及测试输出预算。自适应只适用于供应商和模型明确支持的情况；effort 原样发送至 output_config.effort，不映射为思考预算。可选 low、medium、high、xhigh、max，各值由模型决定，max/xhigh 尤须上游支持；未知模型别名不能据此判断支持。默认 effort 留空使用供应商原生默认值。

对外 Responses 代理

仅支持 POST /responses。管理操作不会调用供应商。上游密钥只引用 Supabase CHAT_KEY_* Secret；下发密钥仅展示一次。

HTTPS 上游基础地址，不得含 response/responses 路径、凭据、查询参数或非 443 端口。这里不输入真实密钥。
