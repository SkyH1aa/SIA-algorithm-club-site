# V10Flash 搜索改造（120 秒预算 + 自研战术层）验收

## 本次改了什么

1. **单步预算 90 秒 → 120 秒**（正式页面、实验页倒计时、对战页 limits 同步）。
2. **新增自研战术层**（`public/gomoku-models/v10flash.js`，Rapfi 内核之外的这一层属于本项目代码）：
   - 威胁识别：活四（·XXXX·，两条成五线）、冲四（单条成五线，逼对手必挡）、活三（·XXX·，下一步可成活四）；
   - **VCF 连续冲四必胜证明**：只搜索"冲四"这一种强制着法，对手每步只有一个合法应手，链条以连五或双四收束。找到即直接落子并跳过引擎；
   - 每步威胁普查写入 `lastSearch.threats`（`openFour`/`four`/`openThree` 计数）。
3. **速度优化**：所有战术扫描限制在棋子邻近空点（成五点必与棋子相邻），不再全盘 225 格扫描；VCF 命中时完全省掉引擎搜索。
4. **完整决策顺序**：立即连五 → VCF 必胜 → 必防对手连五 → 开局先验 → Rapfi 搜索。

## 一次被实测否决的改动

深度上限 16 → 20 曾一并试过：实测出现单步 **85–120 秒**的停顿（`PROGRESS ... 120088`），
违反"速度快"的要求，因此**未采用**，深度上限保持 16。120 秒预算作为上限保留：
深度上限在常规局面远早于时间上限生效，实测均值 1–2 秒、最大约 11 秒。

Rapfi 是编译好的内核，其内部搜索不可修改；`HASH_SIZE`、`THREAD_NUM`、`STRENGTH` 等选项
虽存在于二进制中，但单位与取值范围未经证实，不做盲改。

## 结论与局限

- 改造**没有降低棋力**：对 V10Ultra 保持 2:0，对 V10Exp 保持 1:1；速度维持原水平（均值约 1–2 秒）。
- 战术层是精确的冲四证明，只可能加快或持平，不会引入错误落子；其正确性由
  `node tools/test-gomoku-flash-threats.mjs` 验证（30 个真实局面、6 次必胜声明，
  全部被 V10Exp 独立证明器确认为真；另有活四/冲四/活三/静局/必败等构造用例）。
- **但对 V10Exp 仍是 1:1，没有靠这次改造拉开差距。** 单组空盘换色不构成 Elo 结论；
  要真正证明 V10Flash 强于 V10Exp，需要多开局、多局配对（黑白均 >50% 且统计下界 >50%）。
- 活三（VCT）只做检测与上报，不直接落子：活三是否必胜取决于双方是否有更快的线路，
  硬性规则不成立。这是有意为之的保守选择。
