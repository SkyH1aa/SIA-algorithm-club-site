# 小Bru模型自主选择只读工具

日期：2026-10-19。本轮将助手的实时业务数据选择从关键词/姓名正则路由改为供应商原生工具调用。此文的测试结果在最终验收后补齐。没有自动部署、修改线上数据库、读取真实供应商 Key、请求真实成员数据或发送付费模型调用。

## 用户可见行为

服务端每轮固定注入三个工具的名称、用途和完整 JSON 参数定义，同时以 Responses、Claude Messages 或 Chat Completions 原生工具格式发送给当前已发布助手模型。模型根据用户问题自行选择工具与参数，服务端严格校验后执行，再把带来源编号的结果交回模型作答。

- “帮我看一下当前积分榜谁的积分最高”：`read_member_points`，`order_by=points,direction=desc,page=1,page_size=1`。
- “帮我看一下五子棋排行榜谁的分数最低”：`read_game_leaderboard`，`board=gomoku,order_by=total_score,direction=asc,page=1,page_size=1`。
- “查询张三的积分”：明确的 `member_name` 精确筛选，同名返回 ambiguous，不用班级或账号消歧。
- “接着看下一页”：由模型结合对话选择相同查询的下一页；每次重新读取，不把旧回答当实时证据。

这里的最高/最低由数据库在筛选和分页前排序，不是下载默认前20名后在本地找极值。模型不再依赖 `planAssistantLive` 抽取“姓名”，因此“查询一下”等语气词不会由正则自动成为姓名；模型仍可能理解错误，所以来源同时记录生效的排序、方向和分页范围。模型语义质量需要真实部署后核对，本地模拟只验证调用链的正确执行和限制。

静态社团文档仍采用现有有界检索，不属于本次实时工具选择更换范围。普通 Chat、管理员测试、对外 API 代理和助手压缩保留原路径。数学渲染和用户已有浮窗 UI 保留。

## 可用工具

| 工具 | 参数能力 | 固定数据范围 |
| --- | --- | --- |
| `read_member_points` | 按 points/member_name 升降序、明确姓名、积分区间、分页 | 仅姓名与积分；不输出班级、账号、邮箱、成员UUID、绑定资料 |
| `read_game_leaderboard` | 选择六榜之一、按该榜公开指标排序、明确昵称、分数区间、分页 | 五子棋、俄罗斯方块普通/人机、贪吃蛇普通/人机、行于无垠；只含公开显示名和指标 |
| `read_published_content` | 公告/活动、公开ID、标题字面子串、类别、活动状态、日期区间、排序、分页 | 始终强制已发布；不含作者/更新者UUID，不读取报名名单或后台资料 |

工具 JSON schema 拒绝未知参数，执行器另做独立验证，包括不同榜单允许的排序字段、整数范围、日期、页码和内容类型。模型没有任意 URL、表名、select、SQL、RPC、认证头、管理员 action 或业务写操作入口。公告正文、昵称和参数是数据，不能覆盖固定规则。

人机俄罗斯方块/贪吃蛇的最高分差允许为负数；五子棋按累计积分；行于无垠只查公开总分视图，绝不查账户/进度底表。大整数保持精确。结果位置不自动称为全站排名；筛选后的第1条不等于全站第1名。并列极值和完整人数需要继续核实，不能从单条结果推断“唯一最高”。

## 接口与权限

新增 `club-drive` 动作 `assistant_read_query`，要求已验证登录身份，输入 `{action,query}`。该动作内部只允许 member_points/announcements/events 的固定投影和筛选，不允许客户端提供表名/字段或 published=false。成员积分同名探测在分页和分数筛选前执行，避免用分数条件偷偷选择某个同名身份。原有列表动作不改。

Chat 入口仍要求绑定成员，并检查助手启用、发布模型、供应商、黑名单、额度与租约。管理员/超管使用助手也得到相同成员级范围。新增动作内部沿用 `club-drive` 的服务端数据读取凭据，但这不授予模型管理权限；Chat 工具执行器不使用 service-role。游戏公开读取使用 anon 认证，成员 JWT 仅用于固定 club-drive 查询动作。

固定项目 HTTPS 主机，不跟随重定向，不重试其它密钥或自动切换供应商。站点及对应功能维护开关保留，行于无垠还检查独立的公开服务状态。失败、暂停、空结果、歧义分别返回，非空但字段错误的响应是 unavailable，不再伪装成 empty。

## 调用与预算

一次用户提问最多3次模型请求（两轮可选工具，最后强制不再调用工具），总计最多8次工具执行；每页1–50条、页码1–100。允许查看数据库两端和有界分页，不允许无上限下载或遍历。

每次工具整体最多5秒、原响应最多64 KiB、返回 envelope 最多6000字节。每轮最多24000字节工具结果、48000字节原生工具历史。内容或行数删减明确标记，`has_more` 可为 true/false/null，不虚构总页数和总人数。模型每次请求最大实际序列化字节仍受原有12 MiB限制，原生SSE每轮最多2 MiB。

循环整体最多120秒，仍受 Edge Functions/供应商自身更短限制；超时不是无限运行承诺。用户取消同时中止模型/数据读取。无关问题如果模型不请求工具，则零业务数据读取；catalog和压缩始终不执行工具。

同一提问只有一个 request_id、一次准入、一个租约和一条审计。准入预留最多3次模型输入及有界工具上下文，输出总预算由当前模型默认输出和额度收缩结果共同限制，各轮共享，不能每轮重新获得完整输出。额度不足时可能在调用前拒绝，这是多轮模型请求所需的保守预留。每轮都复核上下文和字节，累计实际模型用量后结算。任一轮缺失完整 usage 则不以较小的部分 usage 退款，保留保守预留；供应商开始后的失败/取消也保留既有保守计量语义。

模型调用发生前的准备/校验失败或取消退款并释放租约；已尝试持久化 upstream_started 后的不确定失败不承诺退款。没有把数据读取当成免费模型规划：语义选择和结果作答都会产生实际模型 token，最终界面用量与审计合并。

## 来源与前端

静态最多4条、实时最多8条，总计12条。静态来源编码头小于4000字符，每个实时来源小于等于980个编码字符，组合头小于12000个ASCII字符。响应头不含数据行和原始筛选值；模型收到完整有界工具结果，前端来源保存时间、状态、排序、方向、页码、每页上限、返回数和是否有后续结果。只显示答案实际引用的合法编号；中英文切换动态刷新。

为了在响应头中携带本轮完整来源并在交付成功前完成审计，工具循环和最终回答先在服务端收集，再按标准 Responses SSE 返回。界面在准备期间维持生成状态，不显示内部工具轮的中间文字、参数或分析；首字可能比普通 Chat 更晚。浏览器历史只保留最终回答和来源，不把模型内部工具历史或密钥放入客户端对话。

结算成功路径遇到一次暂时性 finish RPC 错误时，会以相同幂等结算数据重试；两次均失败时仍进入失败兜底，且不把未确认结算报告为已完成。Claude Messages 的手动 enabled thinking 配置保持原样；工具轮会保留思考预算并给后续最终轮预留至少一个思考预算空间，不足时转为无工具最终轮。

## 网页部署

本轮无 SQL 改动、不新增 Secret。必须在 Supabase 网页分别全文替换并部署：

1. [club-drive-dashboard-index.ts](../chat-deployment/club-drive-dashboard-index.ts) → Edge Functions / club-drive / index.ts。
2. [chat-dashboard-index.ts](../chat-deployment/chat-dashboard-index.ts) → Edge Functions / chat / index.ts。
3. 发布新版 Chat 共享JS、file bundle、助手i18n和预设；若未应用数学更新，保留整个本地KaTeX资源及相关HTML/CSS。
4. 管理页审核保存新版小Bru预设和知识草稿，发布不可变版本；配置副本不是知识JSON。

完整步骤见 [网页部署说明](../chat-deployment/README.md)。只更新预设或只更新Chat不能补齐新的数据查询动作。供应商模型需支持所选协议的原生工具调用；本轮没有实际试调密钥、部署函数或发布线上资料。
