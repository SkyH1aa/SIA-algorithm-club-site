分析日期：2026-10-11。本次只分析，没有改变任何模型源码、搜索参数、权重或训练先验。

1013目前21个记录，其中仅1个V10Ultra记录：`gomoku-20261011121404834-5ea23e88-c0a2-4b8b-b7b4-29e01d2ae80a.json`。这是玩家黑棋、Ultra白棋、31手结束的AI败局。

1014另有Ultra同版本自战的败方记录，不应误算成新增人类击败Ultra的证据。

## 已确认的战术问题

Ultra各手没有错过自身立即获胜落点，也没有漏掉对手的唯一立即连五防点。
但第14手白棋下在**第7行第6列**后，黑棋已能连续冲四强制获胜。独立20层VCF证明器找到路线，另用棋盘连续计数逐步复核了每次唯一防守、白棋没有立即反胜和末尾双获胜点：

从第14手后的局面，11个半回合形成双获胜点，算上白防与黑最终连五共13个半回合。该路线是独立证明的更强续着，不要求玩家实际落子完全相同。
当前Ultra最大深度12，存在搜索视野风险；Rapfi有选择性搜索/延伸，不能直接把配置12等同于每条线严格12，也不能据此断言提高到18必然修复。

对第14手之前所有已有棋子两格邻域的合法白棋候选逐一核验，**第3行第10列**未被证明器找到黑棋VCF，其他候选均被证明有黑棋VCF。它值得作为对比防点，但“未证明败”不能称为安全或保证获胜。
当前上传记录没有PV、实际完成深度、nodes、耗时或资源指纹，无法从棋谱区分时间不足、剪枝遗漏和NNUE评分偏差。

## 当前配置与权重

Ultra页面配置75秒/最多12层/不限节点。桥接每步设置TIME_LEFT=600000；打包配置单线程、TT32MiB、advanced_stop_ratio=0.75。75秒是上限，不代表每步用满，是否需要调整时间管理必须记录真实搜索日志后验证。
页面`lastSearch.depth`当前写的是配置上限，不是Rapfi真实完成深度；不可用它分析实际算力。

当前自由权重位于rapfi.data的6496至10036894字节，大小10030398字节。
SHA256：`6bc0d1b0ff8e1d857f7f412923cd458f38f1a435087c91ae71fec3676c23ef62`。
Git blob SHA：`af04ad2bbb1d95aa5721921627294ef30fdbb0b2`。
已核对官方网络仓库当前树`e32ad77a5364363b3e3a02b3f9e8610ade19ea98`中的同名自由网，blob SHA相同；**换成官方当前同名文件不会升级权重**。
官方同时提供standard和renju网络，它们规则不同，不能用作15×15自由棋的简单替代；文件体积也不等于棋力。

## 建议的实施顺序

1. 先建立独立Ultra增强候选，冻结当前Ultra作对照。记录实际depth/PV/nodes/elapsed和资源SHA256，避免改变配置后把旧12层报告当成真实搜索深度。
2. 在同样75秒预算下，对比12层与更高迭代上限（如18/24）；复杂战术搜索到时间结束，保留上一完整迭代，立即获胜和唯一必防直接落子。用第14手前后局面及八种对称变换回归，验证是否找到第3行第10列等有效防守。
3. 加入独立VCF/VCT战术复核，优先否决能被证明强制输棋的候选，复核备选。增加冲四/活三局面延伸，保留立即获胜优先。已有Exp融合不是自动解答所有Ultra弱点，仍需要该败局的定点验证和完整换色对局。
4. 性能提升从NNUE增量状态、位置键控TT及跨步缓存复用、WASM SIMD、非重复局面计算入手；先测每步START/BOARD对缓存的实际影响，不能未经源代码/日志核实便归因为每步清空TT。多线程另需浏览器隔离头，file://继续单线程兼容。
5. 最后进行权重训练：以当前败局生成困难局面，经更强教师搜索标注最佳动作、胜负/价值和备选；同时混入足量普通局面及双颜色自战，按棋谱划分训练/验证，去除下载副本及确定性重复局。不要给整场每一个局面粗暴打同一loss标签，也不要只靠这一局微调。

官方训练器支持PyTorch训练与Rapfi bin-lz4导出，技术上可训练新权重。但当前打包的是量化压缩推理文件，网络仓库并未列出对应.pt训练检查点；要真正微调需要匹配的可训练检查点，或从训练架构重新训练/蒸馏。原权重不可覆盖，应输出独立新文件。若扩大通道或改变架构，必须同步引擎兼容的评估器、架构hash、序列化与量化，不能塞入一个更大文件就宣称变强。

`node tools/build-gomoku-training-model.mjs`构建的是本项目开局先验，不训练Rapfi NNUE；运行该脚本不能称为优化10MB权重。本次没有重建训练先验，避免把分析请求变成旧模型行为更新。
正式升级应先通过该败局战术回归、双方执色完整对局和设备速度检查，再发布；一场击败原版本或记住该棋谱均不足以证明整体提升。
