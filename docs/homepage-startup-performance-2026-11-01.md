# 首页启动与渲染调度修复

## 用户报告

更新后首页长期停在静态背景，约五分钟后才恢复，同时浏览器和设备卡顿。要求保留 3D 与翻页特效质量。

## 已确认的问题与修复

- three.js 同步脚本位于首页主初始化脚本之前。网络慢时会阻塞章节布局、语言/主题控件和后续共享脚本。改成 DOMContentLoaded 后并行下载两个运行库脚本，等待两者到齐后只启动一次场景。SceneDirector 支持先于 THREE 执行。
- 背景场编译使用 Promise.race，1.5 秒后强制 render，可能让尚未完成的并行编译退回阻塞等待。取消强制启动，严格等待编译就绪。主星系先编译，背景场随后启动。
- 可见性与上下文恢复回调没有统一就绪门禁；页面返回缺乏完整恢复，存在提前绘制与重复循环入口。两层分别加入 ready/paused/contextLost 门禁与单循环检查，恢复时重置时间基准。
- 主场景重复绑定了窗口尺寸变化处理器，包含立即重建与防抖重建。保留防抖重建。
- 初始章节依赖 rAF 才解除隐藏。后台标签中回调可能停住。配置后立即执行一次章节布局，后续动画参数不变。
- sceneMap 中与采样坐标无关的章节、环、节点、连线与伴星变换原本在每个光线步进和法线采样重复计算。改为每片元准备一次并复用；保留原表达式、组合顺序、42/64 步预算与六次法线采样。
- SceneDirector 原使用固定版本号，未包含在资源哈希脚本中。加入版本清单与动态加载 URL 重写。

没有降低粒子数量、几何复杂度、光线采样预算或翻页动效参数。既有自适应画质策略未调整。CPU 数值等价并不意味着所有 GPU 驱动输出逐像素等同，也不代表已测得整机性能收益。

## 验证

- `node tools/test-home-scene-startup.mjs`：运行库两种完成顺序、资源未就绪不启动、主次场景串行启动、隐藏延迟与单次启动；主场景编译/暂停/恢复门禁。
- `node tools/test-scene-lifecycle.mjs`：编译等待、隐藏时就绪、可见性与 bfcache、上下文丢失/恢复、减少动效及 THREE 晚到顺序。
- `node tools/test-scene-field-equivalence.mjs`：2,592 点/材质、2,592 组六次法线、648 条完整光线；CPU 参考数值最大误差 0。
- UI 令牌、资源版本、共享 UI、主题、PWA、词典、收藏与助手回归通过；JavaScript 语法和 diff whitespace 检查通过。
- 内置浏览器确认首屏标题、卡片和入口立即可见；确认新背景 shader 在真实 WebGL 环境编译就绪。

## 验证限制

内置浏览器持续报告 `document.hidden=true`，页面动画帧被暂停。按钮点击自动化等待超时，截图也发生超时。因此未声称完成前台全画质持续帧率、真实翻页或用户设备五分钟问题的完整复现与修复验收。生命周期与翻页参数保留由回归测试及代码差异检查支持，不能替代用户设备实测。

共享观察器未发现自触发循环；SW 为有限请求，未发现缓存更新死循环。SW 路径与缓存失效另有缺陷，但未证实与五分钟整机卡顿相关，本轮未混入离线架构修改。
