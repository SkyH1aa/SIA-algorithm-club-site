   chat-api-proxy does not need redeployment for this repair. If club-drive lacks
   assistant_read_query entirely, use the earlier full live-read upgrade while

   Explicitly check Dashboard > Edge Functions > Secrets for the exact name
   CLUB_SERVICE_ROLE_KEY. club-drive still reads that name; no code fallback to
   SUPABASE_SERVICE_ROLE_KEY or any other name was added. The platform's
   SUPABASE_SERVICE_ROLE_KEY alone is insufficient. If absent, an admin must
   configure it securely in Secrets; never write any key value in docs, code,
   frontend, model configuration or validation records. No new key type or model

   Offline validation passed: 188 real-handler mock cases, 126 plan/SSE cases,

   Steps 2-6 describe optional administration/first setup, not mandatory actions for

7. Runtime contract: an ordinary prompt requests a JSON plan, the server strictly
   validates the entire plan and arguments before any read, and a second model
   request produces the final answer. Full bounded static passages from retrieval
   are retained for the answer, not replaced by source cards or a planner summary.
   A query plan lists at most two fixed reads from read_member_points,
   read_game_leaderboard and read_published_content; clarify and answer plans do
   no business reads but still use the second request for the user-facing reply.
   Normally completed assistant questions use exactly two model requests. Invalid
   plans, insufficient budget, timeout and cancellation may end early; there is no
   planning retry, recursive read, third request or arbitrary URL/SQL/RPC action.
   Native tool support is not required. The configured protocol must provide
   ordinary SSE and a valid JSON plan; malformed plans/protocols explicitly fail.
   Both requests share one request_id, admission, lease, audit and total output
   budget, reserving both inputs and bounded evidence. Planner output consumes
   budget and leaves room for the answer; combine usage for settlement. Keep
   conservative accounting on missing usage or failure after upstream start, and
   refund only when existing database checks prove no upstream start. The planner
   strips reasoning/include and explicitly disables Claude Messages thinking. The
   answer retains configured thinking/reasoning within the remaining shared budget;
   only the answer needs the Claude enabled-thinking minimum, not a second thinking
   minimum for planning. Daily admission uses the UTC day bucket (08:00 Beijing
   reset), not the 90-day audit report; raising limits does not clear existing usage
   or unsettled reservations.
   Planning, reads and final answering share a 120-second overall deadline and
   cancellation. Each of at most two reads keeps its 5-second/64-KiB raw/6000-byte
   envelope limits; aggregate serialized evidence is <=16000 bytes and the JSON
   plan is <=8192 bytes. Keep page 1..100, page_size 1..50, model request <=12 MiB
   and upstream SSE <=2 MiB per request.
   Audit error_code records safe categories only, without raw plan/arguments/results,
   provider bodies, authentication headers or keys:
   assistant_plan_json, assistant_plan_invalid, assistant_plan_arguments,
   assistant_plan_size; assistant_plan_http, assistant_plan_network,
   assistant_plan_stream, assistant_plan_usage; assistant_answer_http,
   assistant_answer_network, assistant_answer_stream; assistant_output_budget,
   assistant_context, assistant_request_size, assistant_evidence_size;
   assistant_plan_failed as the unclassified fallback. Existing auth/quota/database/
   cancellation/protocol categories remain. See semantic-read-tools.md for meanings;
   an error category does not establish successful reads or refund eligibility.
8. After a separately authorized deployment, verify login/binding, source links,

   Deployment and live publication remain separate administrator actions.
