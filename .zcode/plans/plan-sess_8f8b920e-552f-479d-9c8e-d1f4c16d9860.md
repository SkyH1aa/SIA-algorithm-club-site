## 一、新增共享前端基础层（解决重复代码、确认框、撤销、空态、401）

新建 `public/club-common.js`（自包含，自带样式注入，不依赖 club-ui.css，因此 chat / assistant / platformer 也能用），并暴露：

- `ClubCommon.escapeHtml(value)`
- `ClubCommon.confirm({ title, message, confirmText, cancelText, danger })` → `Promise<boolean>`，统一对话框：`role="dialog" aria-modal="true"`、焦点圈闭、Esc 取消、亮暗主题、移动端全宽。
- `ClubCommon.scheduleUndo({ message, undoLabel, onCommit, onUndo, seconds:5 })` → 右下角倒计时提示条，5 秒后执行删除；点“撤销”取消；页面 `pagehide` 时用 `fetch(..., {keepalive:true})` 补提交，避免关页丢失。
- `ClubCommon.listState(container, { kind:'loading'|'empty'|'error', message })` → 统一骨架屏 / 空结果 / 加载失败三种状态。
- `ClubCommon.handleAuthError(response, payload, fallbackMessage)` → 401 时抛出带 `status=401` 的“登录已过期”错误，并广播一次 `club:session-expired`；`club-common.js` 监听后显示顶部可关闭提示条（含“前往个人中心”链接）。

**替换范围**
- `escapeHtml`：删除 21 处本地实现，统一用 `ClubCommon.escapeHtml`（保持输出逐字节一致）。
- `confirm()`：18 个文件约 44 处全部替换。同步函数（如 `chat.js:regenerate`、`tetris.js` 的 `surrender`）改为 `async`，调用点改成 `void fn()` 或 `await`；`chat-file-bundle.js` 由构建脚本重新生成，不手改。
- `call()` 401：15 个页面的请求助手统一调用 `handleAuthError`，不再把过期显示成“操作失败”。

**撤销落地页**：捐赠名单、社员留言、积分商城商品删除。确认框取消，直接进入 5 秒可撤销窗口。

5. **CSV 导出**：导出当前筛选结果（含 BOM，Excel 中文不乱码），字段为捐赠人、日期、金额，文件名带日期。

同时把捐赠列表的 loading / empty / error 接到 `ClubCommon.listState`，区分“正在读取”“暂无记录”“读取失败”。

## 风险与边界

- 确认框异步化会触及游戏与 Chat 管理流程，逐处改后跑对应 UI 测试；不改业务判断条件，只改等待方式。
- 撤销窗口内页面被强杀时，`keepalive` 也可能失败；届时记录留在本地提示“删除未完成，请重试”，不谎报成功。
- 资源版本号工具会重写 37 个 HTML，只改 `src`/`href` 的查询串，不动其它内容；先备份式 diff 审核。
- 本地化 Supabase 需要一次性下载，版本固定并在文档记录；不引入构建步骤或 npm 依赖。
- 所有改动仍不触碰训练数据、模型资产和已有 SQL 迁移；仅捐赠功能不改 SQL（配置表上一轮已建）。
