# Markdown / 数学公式修复与小Bru实时只读查询

## 已确认范围

- AI Chat 和小Bru共用修复后的 Markdown、数学公式渲染。
- 实时查询仅加入小Bru；仍要求登录并绑定社员。
- 积分查询只向模型提供姓名和积分，不提供班级、账号、邮箱、用户 UUID、绑定记录。
- 游戏查询覆盖现有六个榜单：五子棋积分榜、俄罗斯方块普通/人机榜、贪吃蛇普通/人机榜、行于无垠总分榜。默认每榜前20名，各榜独立，不合并分数。不增加模型强度排名或模型对战统计。
- 公告和活动只读已发布内容。管理员、超管使用助手时也仅获得同样的成员级结果。
- 不部署、不改线上数据库、不读真实密钥、不调用付费上游、不 commit/push，保留用户已有UI和无关修改。

## 1. 修复 Markdown 与数学公式

现状：`public/chat.js` 的 `markdown()` 已使用 Marked 和 DOMPurify，普通正文粗体等应能渲染，但没有 LaTeX 渲染器。示例中的 `\(...\)`、`\[...\]` 会显示为原始文本，部分转义还可能被 Markdown 解析提前处理。

实施：

1. 本地引入固定版本 KaTeX 浏览器脚本、CSS、字体与许可证，不在运行时从外网加载。
2. 在两页面共用的渲染器中，用 Markdown token 扩展识别数学区段，先保护数学内容，再净化 Markdown，最后用 KaTeX 渲染专属节点。覆盖 `\(...\)`、`\[...\]`、`$$...$$`；单美元语法采用保守规则并测试价格、转义美元，避免把货币误作公式。
3. 代码围栏、缩进代码和行内代码保持字面内容；不对整段回答做盲目正则替换。流式接收中缺失结束符或非法公式保留可读原文，完整后再排版。
4. KaTeX 禁用可信 HTML/外链能力，限制展开次数、尺寸、公式长度/数量；每次独立宏状态。模型原始 HTML 继续经过现有净化，不为数学放宽原始 HTML 的 SVG/MathML/style 权限。
5. 保留原始对话文本、复制、导出和后续上下文，不把渲染 HTML 写回历史。
6. 局部CSS适配亮暗主题、手机和浮窗，长公式可横向滚动，不撑破布局。保留用户刚修改的UI结构、拖拽与样式。
7. 同时复核用户示例中的粗体、段落、列表、表格和代码；若普通回答仍出现原始 Markdown，针对复现修复，不把代码或用户输入中的字面 Markdown强行转换。

## 2. 实时查询的权限与接口

新增独立服务端只读适配器，使用写死的来源、请求动作和字段投影。模型和客户端不能传任意 URL、表名、RPC、SQL、select、认证头或目标账号。

复用现有成员读取路径：

- `club-drive` 的 `announcements_list`、`events_list`：仅已发布内容，去掉作者/编辑者UUID等非展示字段。
- `club-drive` 的 `member_points_list`：携带经过验证的当前成员 JWT，输出只保留姓名、积分与查询所需排序。按姓名提问可匹配，重名不猜账号；不提供无限枚举或深分页。
- 六个排行榜：用公共凭据读取现有公开排行榜表/视图，明确字段、排序和 limit，绝不读取游戏账号底表、会话、密码、PK房间或积分修改接口。

公告和积分的现有 edge action 内部可能使用 service-role 读库，但它们是固定的公开/成员接口。新适配器不使用 Chat 的通用 service-role `rest/rpc` helper查询业务数据，也不因提问者是超管就选择管理员 action。

明确排除：未发布公告、报名名单、成员绑定目录、权限名单、密钥、管理日志、后台读接口；以及签到、报名、兑换、奖励领取、积分修改、分数提交、训练上传、对战记录写入等所有业务写操作。原有生成的额度与审计写入继续存在，它们不属于新增社团查询权限。

## 3. 查询选择、时效与回答

第一版采用服务端可审查的确定性查询路由，不依赖各供应商不同的 tool-calling能力，也不额外调用模型规划查询：

- 根据当前真实用户问题及有限近期追问，识别公告、活动、积分及指定游戏榜单；排除附件正文、旧助手回复和摘要中的查询指令。
- 仅取问题涉及的数据；“全部游戏榜单”每榜取小范围结果。缺少游戏/榜单类型时澄清，不默认混淆普通与人机榜。
- 只承诺榜单前20名及明确的数据范围；查不到不能推导全站没有该人。
- 公告和活动保留发布日期、开始/结束、状态等事实，不把“已发布”自动视为“今天有效”，不从容量推算剩余名额。
- 五子棋按累计积分；人机俄罗斯方块/贪吃蛇按最高玩家减AI分差（可为负）；行于无垠按各关最佳分累计。响应明确分数含义，不称为模型棋力排名。
- 每次相关问题重新读取，附服务端查询时间、来源页面、榜单类别、截断范围；超时/失败/无匹配分别说明，不用旧摘要充当实时证据。
- 查询文本和昵称同样是不可信参考数据，不能触发新操作或覆盖规则。
- 尊重站点/相关功能的维护开关，关闭时显示实时查询暂不可用，不读取被关闭功能作为绕过入口。

## 4. 共享额度、预算和来源展示

- 实时数据仅用于 `assistant_respond`，catalog和上下文压缩不发起业务查询。
- 增加明确的每轮请求数、超时、行数、响应字节、单字段与总注入预算；仅访问固定项目地址，禁跟随重定向到任意外站。
- 查询挂接在现有共享生成准入/并发限制之后、付费上游请求之前。按实时数据最大预算预留并再次校验实际上下文；取消、准备阶段失败与结算沿用现有语义，不以查询异常绕过租约或额度。
- 新增来源类型/查询时间信息，与静态发布UUID区分；卡片仍只展示正文实际引用的合法编号，指向对应站内页面，不将数据表或API地址做为用户链接。
- 实时正文不塞进响应头，来源头维持有界；更新前端上下文预留与服务端最终校验。
- 共享业务流程支持Responses、Messages和Chat Completions；无需向供应商开放直接数据库、MCP或浏览器工具。

## 5. 更新预设与部署材料

- 更新小Bru固定规则、预设Prompt及知识：从“完全没有实时访问”改为“仅本轮提供的白名单只读查询结果可作为实时依据”，保留不代操作和未知说明。
- 修改 `supabase/functions/chat/index.ts`、共享助手模块及新增实时适配器；前端仅增加必要的数学加载与实时来源呈现。
- 优先复用现有接口，本轮计划不新增SQL权限或业务写接口。若实现中发现现有接口无法满足限制，先明确报告，不扩大为管理员查询。
- 重建 `chat-file-bundle.js`、预设副本和Dashboard单文件。继续提供 Supabase 网页全文粘贴部署说明，不要求使用CLI；保留原发布快照和草稿语义。

## 6. 验证

数学渲染使用真实 Marked、DOMPurify和KaTeX测试，不能只靠现有stub：

- 用户提供的完整物理题、粗体、分式、上下标、单位、boxed、多行公式。
- 流式半截公式、停止/中断、非法TeX、安全回退、代码不被转换、货币文本。
- 恶意Markdown/TeX、危险链接、原始HTML、宏展开/超长公式边界。
- 普通Chat与助手、桌面与窄浮窗、亮暗主题、长公式滚动；HTTP与file包加载一致性，平台不支持的实测项明确记录。

实时查询测试：

- 未登录/未绑定拒绝；普通成员、管理员、超管得到同一成员级字段。
- 白名单之外动作、管理员数据、任意URL/SQL/RPC/账号目标无法进入适配器；断言新增业务调用只有读动作。
- 只暴露姓名积分；排名分数语义、重名、负分、精确整数、截断/排序、已结束活动处理。
- 无关问题零查询；相关追问、主题切换、附件注入不扩大查询范围。
- 超时、失败、空结果、取消、维护状态、总预算、来源引用和查询时间。
- 共享quota/租约/取消结算、三协议回归、预设及Dashboard一致性、真实类型检查。
