## Context
在现有 AIChat 内增加「在线生图」工作台，参考截图的三栏操作关系，沿用官网 Chat 的亮暗主题与账号体系，不重做普通对话，也不扩展视频、提示词市场等无关功能。

已确定的业务要求：
- 只有超管在 Chat 管理中配置的生图模型可以使用；生图与普通 Chat、社团助手双向隔离。
- 提供 Images、Chat/Responses 和自定义兼容端点接入；支持原样配置供应商给出的 `/v1/response`。
- 生图独立按张计额，不占聊天 token；展示近 90 天生成总张数，设置每日全站、默认每人上限，并可单独调整用户上限。
- 每个账号的每次生成都在本机保存提示词、参数和真实图片，同时向现有 123 云盘留档。

## 1. 模型配置与服务端隔离
修改 `supabase/club-chat-schema.sql`、`supabase/functions/chat/index.ts`、`public/chat-admin.html`、`public/chat-admin.js` 及管理页词典/样式。

- 为 `chat_models` 增加明确的 `purpose: chat | image` 与图片配置 `image_config`。历史模型默认 `chat`；旧客户端保存时省略新字段，保留现有用途和配置，不误改模型类型。
- 复用供应商、Base URL、认证头、`CHAT_KEY_*` Secret 引用、启用状态、模型介绍及已有用户授权，不另建一套密钥系统。
- 管理表单增加「对话 / 生图」用途。生图模式显示接口格式、端点、质量、尺寸、透明背景、参考图等能力配置；隐藏不适用的上下文与思考参数。原 `supports_images` 明确仍是“聊天理解图片”，不作为生图标记。
- 普通 Chat 的 `catalogPayload()`、`modelWithProvider()`、实际调用、管理员文本测试，以及助手模型选择、保存、发布和运行均拒绝 image 模型。生图目录与执行路径反向拒绝 chat 模型。
- 生图每次执行重新验证账号、资料绑定、黑名单、模型授权、模型/供应商启用及删除状态；浏览器不能自行提交上游 URL、Secret、模型 ID 或任意请求参数。
- 同一上游模型可按用途分别配置，相关唯一约束按用途调整，保留历史模型与审计引用。

## 2. 生图接口与执行链路
在现有 `chat` 边缘函数中增加图片专用动作和独立共享模块，例如 `_shared/chat-images.ts`、`_shared/chat-image-media.ts`；不把大图挤入现有文本 SSE 解析器，也不借用绕过成员配额的 `chat-api-proxy`。

### 接口配置
- **Images**：标准 generations；有参考图且配置支持时走 multipart edits。
- **Responses / Chat Completions**：分别构建对应请求，解析明确的图像结果；Responses 支持配置直接生图模型或标准 image-generation tool 模式，不根据模型名称猜测。
- **自定义 v1 兼容端点**：超管指定精确端点与上述请求/结果格式，可配置受限字段映射和固定参数；只进行声明式映射，不执行脚本、不允许任意 Header/URL 透传。
- Base URL 与完整端点分清处理，管理页展示最终请求地址。完整 `/v1/response` 保持单数，不追加 `/responses`，不静默换端点重试。旧聊天协议行为不变。
- GPTimage 2/2.5/2.6 的真实模型 ID、quality 值和尺寸能力由超管按供应商填写，不硬编码未经证实的型号或六档质量。

### 批量与边界
- 一次操作可选 1–10 张；采用一批预留、逐张执行、逐张保存和展示，避免十张 4K 图片同时滞留于一个 Edge 请求。每个槽位有独立且稳定的请求标识，重复点击或网络重试不会再次发起已执行槽位。
- 请求指纹绑定模型、提示词、参数和参考图；每张执行前核对，不能借已预留批次替换请求。
- 设置有界请求体、单张输出、总响应、图片像素、参考图数量、读取时间和上游超时；与前端、归档上限共用明确约定。超限给出错误，不静默降质或丢图。
- 优先解析 base64/二进制结果；远程图片仅允许经过校验的公网 HTTPS 来源和管理员允许的媒体域名，禁止重定向，不携带供应商 Key，校验真实字节、类型与图片签名。参考图仅接受用户上传/粘贴的真实文件，不提供任意 URL 服务端抓取入口。
- 生成耗时展示真实阶段与已完成张数，不伪造模型百分比。停止时取消未开始的槽位并尝试中止当前传输，明确说明供应商可能仍在生成；不自动重试不确定请求，不承诺无限后台执行或刷新后恢复上游任务。

## 3. 图片额度、统计与幂等结算
在完整主 SQL 中幂等增加图片专用配置、日桶、批次/槽位和用量 RPC，RLS 与执行权限沿用服务端受控原则，不改聊天 token 配额。

- 全站每日上限、默认每人每日上限、个别用户覆盖；`0` 为禁止，留空为不限。新功能首次默认关闭，超管设定额度并启用模型后开放，不猜测具体可消费张数。
- 生图日界按北京时间 00:00，界面显示重置时间；不改变普通 Chat 已有的日界和 token 账本。
- 在同一数据库事务中锁定并检查全站/用户额度，按整批张数原子预留。不足时整批拒绝，不偷偷减少张数。
- 逐槽位原子领取、幂等结算：确认成功的图片计入“已生成”；尚未开始的取消/过期槽位可以释放；已提交上游但超时、断线而结果未知的槽位保留为“不确定占用”，不能冒充成功，也不能无证退款后自动重跑。
- 后端支持超管查看异常占用并在明确确认后核销；所有调整留审计，重复结算不重复扣减或退款。
- Chat 管理新增近 90 天实际生成总张数、今日全站与用户用量/预留，以及按用户、模型、时间和状态分页的图片使用记录。审计仅存必要元数据，不存提示词、Key 或图片正文。
- 90 天是统计窗口，不据此删除本机图片或 123 留档。

## 4. 在线生图工作台
新增 `public/chat-images.html`、`chat-images.css`、`chat-images.js`，以及独立 core/store/i18n 模块。在 `public/chat.html` 顶栏加入「对话 / 在线生图」链接，生图页提供返回对话和个人中心入口。

桌面三栏：
1. **生成记录**：数量、新建、选择/全选、批量删除，展示缩略图、提示词摘要、时间、生成及归档状态。
2. **生成设置**：提示词；参考图上传、拖放、剪贴板粘贴与移除；模型、质量；宽高与交换、16 倍数校验；1k/2k/4k/自动、截图中的比例预设；透明背景；1–10 张；额度提示和生成/停止按钮。
3. **结果区**：空态、进行中、逐张结果、部分成功/失败说明；大图预览、下载原图、复制提示词、复用参数再次生成。

- 所有参数只显示和提交当前模型实际配置支持的选项；不支持参考图/透明/自定义尺寸时禁用并说明原因。分辨率与比例换算得到实际尺寸后明确展示，不把界面标签当作供应商必然支持的 API 参数。
- 平板收缩记录栏，手机使用记录抽屉、设置与结果自然纵向排列，保持主要操作可达，不压缩成三个窄栏。
- 复用 Chat 的登录门禁、主题、确认弹层和错误呈现约定；提供无模型、无权限、额度不足、网络错误、归档失败和本地空间不足等状态。
- 集中刷新动态文案，保存 i18n key 与原始变量，监听 `club:langchange` 并补一次延迟刷新；支持中英文、亮暗主题、键盘焦点、拖放的按钮替代及减少动态效果。

## 5. 本机持久保存与 123 云盘留档
### 本机
- 独立版本化 IndexedDB，元数据与 Blob 分开，按 `userId` 隔离，记录分页读取、图片按需加载，不使用旧 `createChatStore().list()` 把所有大图 `getAll()` 到内存。
- 保存每次请求的提示词、参数、模型、时间、参考图、生成图、结果与归档状态，真实 Blob 不替换成临时 URL。
- 处理账号切换后的异步过期响应、Object URL 释放、存储配额不足和刷新恢复；空间不足明确告警并保留当前结果下载入口。

### 云盘
- 扩展 `supabase/functions/club-drive/index.ts`，为生图提供专用快照与图片归档动作，复用已验证身份推导目录、北京时间命名、SHA-256 校验和附件分离机制。
- 生图记录写入现有 `/Chatdata/<账号目录>/` 下的独立生图区域；提示词、参数和图片引用进入可读 JSON，参考图与生成图按哈希存真实文件，不把 base64 反复嵌入快照。
- 图片专用上传上限与生图输出一致，避免旧 6 MiB 附件限制导致大图缺失；逐张上传，校验真实字节与哈希，不放宽普通聊天附件规则。
- 服务端取得生成结果后即尝试将提示词及图片送入同一归档链路，再向页面报告归档状态；浏览器保存本地副本，并持久记录待归档队列，在线/重新登录后可重试失败项。上传图片和快照全部确认后才标记“已留档”。归档失败不重新调用生成模型。
- 删除本机记录须确认且先完成归档；归档失败保留本机数据。删除本机不删除 123 历史留档，文案明确区分。
- 页面说明如实写“本机保留，同时上传社团 123 云盘留档”，不声称仅本机或本次结果不留存。
