算法社官方网站开发日志 Report

项目名称：新哲文院算法社官方网站
项目类型：社团综合门户、算法教学平台、在线工具与成员管理系统
项目状态：持续开发与迭代中
主要技术：HTML5、CSS3、原生 JavaScript、Supabase、PostgreSQL、Edge Functions
部署形式：静态网页部署，可兼容 GitHub Pages 等静态托管平台

一、项目概述

我为新哲文院算法社设计并开发了一个综合型官方网站。网站不只是展示社团信息的静态页面，而是将社团介绍、活动通知、教学资源、算法实验、AI 对战、成员服务、社团盘和软件项目展示整合到同一套前端体系中。

网站的建设目标是降低成员获取学习资料和参与活动的成本，同时把抽象的算法知识转化为可交互、可观察、可重复实验的网页工具。网站也承担社团项目展示、成员身份管理、积分激励和后续扩展的基础设施作用。

二、网站功能架构

1. 首页与社团展示

首页提供社团品牌、项目介绍、活动入口、成员信息和功能导航。页面使用统一的主题变量、响应式布局和动态背景效果，并支持中文与英文双语切换。首页还提供项目数据驱动的展示方式，项目、成员、活动和更新记录分别由 JSON 数据文件维护，便于持续更新。

2. 社团功能中心

社团功能页集中展示当前开放的工具和服务，包括 APPMonitor、AI 五子棋、AI 俄罗斯方块、AI 贪吃蛇、算法可视化实验室、教学资源和《行于无垠》游戏。每个项目具有状态、类型、简介和入口，形成清晰的项目索引。

3. 算法可视化实验室

网站提供排序、搜索、数据结构、图论最短路、动态规划、二叉树和堆等实验室。实验室支持连续播放、单步执行、速度调节和过程状态展示，帮助使用者观察算法每一步的变化，而不是只查看最终答案。

4. AI 对战与算法项目

网站接入 AI 五子棋、AI 俄罗斯方块和 AI 贪吃蛇。项目同时保留正常游玩模式与 AI 演示、辅助或对战模式，并通过排行榜记录成绩。开发过程中重点处理了随机序列一致性、AI 行为边界、得分保存和客户端状态恢复等问题。

5. 教学资源中心

资源中心提供 Python、C++ 教材及对应答案解析，并通过统一页面入口管理 PDF 资料。资源页面考虑了下载路径、移动端阅读和静态部署下的相对路径兼容性。

6. 成员服务与社团盘

网站包含成员注册、登录、成员资料、签到、积分、积分商城、消息、加入申请和社团文件管理等模块。成员身份由统一的前端身份模块维护，权限相关操作通过 Supabase 数据库规则和服务端函数进行约束。

7. 活动与公告系统

活动页面支持活动列表、活动详情和状态展示；管理员页面支持创建、编辑和维护公告。公告可以向成员展示弹窗通知，并扩展附件或奖励领取逻辑，用于社团活动发布、版本更新和重要提醒。

8. 管理后台与权限控制

管理员中心负责成员审核、积分管理、公告管理、文件管理和权限配置。系统区分普通成员、管理员及社团超级管理员，避免把高权限操作直接暴露在普通用户流程中。涉及金币、积分、活动奖励和服务开关的操作均保留服务端校验入口。

三、技术实现与工程设计

1. 前端结构

项目采用多页面静态网站结构，每个功能模块使用独立 HTML 页面，公共主题、国际化、身份识别和服务状态脚本集中放置在 public 目录。这样既保持了部署简单，也使算法实验、游戏和管理页面之间保持相对独立。

2. 主题与国际化

网站建立了统一的 theme.css 和 theme.js，支持明亮、暗色等主题切换，并通过 i18n.js 与 i18n-dict.js 管理中英文文本。页面标题、导航、按钮和提示语均尽量使用词典键，减少重复文案和主题切换时的维护成本。

3. 数据与后端服务

Supabase PostgreSQL 用于保存成员资料、积分、签到、排行榜、活动和权限数据。对于需要原子更新或权限判断的操作，使用 SQL 函数、RLS 和 Edge Functions 进行服务端处理，避免仅依赖浏览器端数据。

4. 静态部署兼容

网站所有页面均使用相对路径组织资源，兼容本地静态服务器和 GitHub Pages。开发过程中重点检查了首页、public 子目录、PDF 资源、图片素材、脚本加载和直接访问深层页面时的路径问题。

四、主要开发阶段

阶段一：完成官网基础页面、导航、社团介绍和主题视觉体系。

阶段二：加入成员资料、活动、教学资源、项目展示和双语词典。

阶段三：开发算法可视化实验室，并接入五子棋、俄罗斯方块和贪吃蛇等交互项目。

阶段四：建设签到、积分、商城、社团盘、消息和加入申请等成员服务。

阶段五：接入 Supabase 数据存档、排行榜、权限控制、公告、奖励和管理员后台。

阶段六：持续修复本地打开、静态部署、移动端布局、主题切换、身份恢复和服务开关等兼容性问题。

五、问题定位与解决经验

项目开发中遇到过路径错误、深层页面无法访问、数据库函数参数冲突、权限边界不清、重复领取奖励、移动端控件溢出和客户端状态不同步等问题。

解决这些问题时，我逐渐建立了较完整的排查流程：先通过浏览器控制台和服务端日志确定错误边界，再检查页面生命周期、数据库函数签名、RLS 策略和数据更新顺序，最后使用本地服务器、不同账号和不同屏幕尺寸进行回归验证。对于奖励、积分和权限等关键数据，优先将校验放到服务端，降低客户端篡改风险。

六、项目成果

1. 建立了一个包含展示、学习、实验、游戏和成员服务的算法社综合官网。
2. 实现了七类算法可视化实验室，支持单步和连续演示。
3. 接入多个 AI 互动项目，并提供排行榜和成绩记录能力。
4. 提供教材、答案解析、活动、签到、积分商城和社团盘等实际服务。
5. 实现统一主题、双语支持、响应式布局和静态部署兼容。
6. 建立 Supabase 数据库、RLS、RPC 和 Edge Functions 的后端基础。
7. 将权限、公告、奖励和服务开关纳入管理员工作流。

七、个人收获

这个项目让我从制作单个网页，逐步转向设计和维护一个包含多种用户角色与数据流的综合系统。我实践了前端组件复用、数据驱动页面、交互式算法教学、数据库建模、权限控制、服务端校验、静态部署和跨设备适配。

更重要的是，我认识到网站功能越多，越需要清晰的模块边界和一致的数据规则。一个按钮背后可能涉及身份验证、数据库写入、权限判断、错误提示和页面状态恢复。通过持续排查问题，我提升了阅读日志、定位根因、设计回归测试和维护长期项目的能力。

八、后续计划

1. 继续优化首屏加载速度和图片、脚本资源体积。
2. 增加更系统的访问统计、错误监控和自动化测试。
3. 完善管理员操作审计和更细粒度的 RLS 策略。
4. 增加更多算法实验、课程内容和成员协作工具。
5. 进一步改善移动端体验及不同浏览器下的兼容性。
6. 完善 GitHub Pages 与 Supabase 的正式部署文档。

总结

新哲文院算法社官方网站是一个由我持续设计、实现和维护的综合项目。它将社团展示、算法教育、互动游戏、成员管理和云端服务结合起来，体现了我从页面开发向完整软件系统开发的成长。项目过程中形成的需求拆解、模块设计、数据建模、错误定位和持续迭代经验，是我申请大学时最重要的工程实践成果之一。
